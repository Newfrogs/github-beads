# Complete-guide expansion of GitHub Beads

Source: https://agent-flywheel.com/complete-guide, read in full on 12 October 2026.
Baseline: GitHub Beads 0.2.0, commit 34ac7c0.

## Outcome and boundaries

Make the reusable Claude Code/Codex package cover the guide's whole useful workflow: discovery, planning, translation, coordinated execution, integration, recovery, delivery, and evidence-driven learning. Account for every substantive guide section, operator, prompt family, tool, and deployment caveat in a source-to-implementation map. Write original instructions rather than republishing the guide.

Retain the existing plan-only, Beads-only, full, and resume modes. Optional tooling stays optional. Do not impose the guide's fixed plan lengths, time percentages, review quotas, model roster, fabricated mismatch counts, mandatory VPS, shared-main requirement, or permission bypasses. Adapt those recommendations to the current repository, actual capability, observed uncertainty, and user authorization. Evidence-before-ceremony governs stopping and completion claims.

## Design and order

Keep SKILL.md a compact router. Extend focused references and add swarm, toolchain/learning, and existing-project guidance where needed. Add reusable assets only when they help an agent execute the workflow. Preserve the auditor's read-only contract; an optional completion gate checks actual native status rather than pretending to prove code semantics. Require separate acceptance evidence.

1. Read the entire guide, record scoped requirements, initialize the absent repository-local br store, create actual tasks and coverage.
2. In parallel implement planning/conversion, coordination/execution, and toolchain/learning references. Root integrates routing and implements the completion auditor.
3. Merge the complete source map and detailed TODO with actual Beads IDs. Check links, package manifests, and source coverage.
4. Run meaningful auditor regressions and an independent behavior probe; repair observed defects only.
5. Record evidence and close finished tasks; export, inspect and publish original package/docs/tracker artifacts. Update local clients and verify remote CI and installed contents.

## Verification and limits

Use Python unittest on Windows locally and Windows/Linux CI for deterministic helpers. Use the checksum-verified native br 0.7.4 binary with an explicit repository-local database path for actual tracking. Strict Claude manifest validators and Codex skill validation check packaging. An independent agent receives the updated skill and a raw isolated repository request, without a prescribed solution.

A complete guide inventory does not imply all optional external tools were installed or exercised. Distinguish real br operations, behavior probes, source-checked integrations, and untested external services/other clients in the final receipt. Do not test permission bypasses, credentials switching, paid subscriptions, VPS provisioning, or deployment.
