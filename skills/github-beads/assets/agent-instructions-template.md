# Repository operating contract template

Merge relevant sections into the project's existing `AGENTS.md` or `CLAUDE.md` under that client's normal instruction rules. Resolve placeholders, remove unused tooling, and preserve established policies. Do not copy this template over an existing file or treat its example fields as discovered facts.

## Project and source of truth

- Repository: `<actual repository and checkout>`
- Goal and boundaries: `<observable user outcome; material exclusions>`
- Architecture and conventions: `<actual source/docs paths>`
- Markdown plan: `<saved plan path>`
- Requirement coverage: `<coverage map path>`
- Tracker: `<existing br or bd backend; configuration and native sync policy>`
- Beads owns task status/dependencies. Plans own intent; receipts preserve evidence.

## Execution and collaboration

- Branch/review and publication policy: `<actual repository policy>`
- Required checks and acceptance commands: `<commands inspected in this repository>`
- Shared-checkout or worktree policy: `<host/repository convention and integration owner>`
- Ownership: refresh actual state, claim through the native tracker, preserve live claims and others' changes.
- Optional Agent Mail: `<configured project key and tool discovery; never credentials>`
- Optional reservations: use narrow paths, inspect grants and conflicts, renew active work, release the task's leases.
- Use actual bead IDs in threads, reservation reasons, evidence and authorized commits.
- Communication: `<authorized participants/channel; host policy>`; target affected workers and avoid redundant broadcasts.
- Optional routing/build/scan tools: `<installed tools and version-help paths>`; do not invent commands or install the whole stack.
- Preserve instruction and tool guards. Diagnose a refusal before retrying; never bypass it to claim completion.

## Completion and recovery

- Inspect changed behavior and the final diff; run required and task-relevant checks.
- Record actual outcomes, files, checks/results and acceptance evidence before closing a bead.
- Update the plan/map and reconcile actual beads when scope or prerequisites change.
- After compaction, reload instructions, the source and tracker state, then recover the current claim.
- Resume receipt: `<existing project handoff path>`; include actual IDs, partial changes, evidence, blockers and the next action.
- Stop reviews when the relevant question is resolved; revisit for a new change, finding or required gate.
- Publication/deployment: `<existing user authorization and repository requirements>`; report local and remote states truthfully.

## Bounded worker kickoff packet

```text
Work in <actual repository/checkout> under its current instructions.
Read <instruction paths>, <plan path>, <coverage path>, and actual bead <ID>.
Use <selected backend>; refresh task ownership/readiness before claiming.
Deliver <bead outcome> within <scope and constraints>.
Expected edit surface: <specific paths; proposed if not yet confirmed>.
Coordinate through <authorized channel/project>, respecting live reservations.
Run <repository-required and acceptance checks>; record actual evidence in the bead.
Integrate through <shared-checkout/worktree policy and integration destination>.
If blocked, record the cause and continue useful independent authorized work.
On handoff, preserve partial changes and leave <resume receipt path> with actual state.
```
